# Linux Remote Management Protocols

## 1. Tổng quan

Các giao thức quản lý từ xa cho phép quản trị viên truy cập, quản lý và xử lý sự cố máy chủ mà không cần có mặt trực tiếp. Trong Pentest, cấu hình sai hoặc thông tin xác thực yếu có thể dẫn đến truy cập trái phép.

Ba nhóm dịch vụ chính:
- SSH
- Rsync
- R-Services

---

## 2. SSH (Secure Shell)

- **Port mặc định:** TCP/22.
- Tạo kết nối mã hóa giữa client và server, hỗ trợ thực thi lệnh, truyền file và port forwarding.
- `SSH-2` an toàn hơn `SSH-1`; SSH-1 dễ bị tấn công MITM.
- OpenSSH là triển khai SSH phổ biến trên Linux.

### Các phương thức xác thực

1. Password authentication
2. Public-key authentication
3. Host-based authentication
4. Keyboard-interactive authentication
5. Challenge-response authentication
6. GSSAPI authentication

### Public Key Authentication

- Client giữ **private key**, server lưu **public key**.
- Private key cần được bảo vệ bằng passphrase mạnh.
- Client chứng minh quyền sở hữu private key để xác thực với server.
- Cần xác minh host key của server để tránh kết nối tới máy chủ giả mạo.

### Cấu hình nguy hiểm

| Cấu hình | Rủi ro |
|---|---|
| `PasswordAuthentication yes` | Có thể bị dò mật khẩu nếu không có biện pháp bảo vệ phù hợp |
| `PermitEmptyPasswords yes` | Cho phép mật khẩu rỗng |
| `PermitRootLogin yes` | Cho phép đăng nhập trực tiếp bằng root |
| `Protocol 1` | Sử dụng giao thức SSH cũ |
| `X11Forwarding yes` | Cho phép chuyển tiếp giao diện đồ họa X11 |
| `AllowTcpForwarding yes` | Cho phép chuyển tiếp TCP |
| `PermitTunnel` | Cho phép tạo tunnel |
| `DebianBanner yes` | Hiển thị banner đặc trưng của Debian |

Kiểm tra cấu hình SSH:

```bash
cat /etc/ssh/sshd_config | grep -v "#" | sed -r '/^\s*$/d'
```

### Footprinting SSH

Sử dụng `ssh-audit` để kiểm tra phiên bản, thuật toán mã hóa và cấu hình SSH:

```bash
git clone https://github.com/jtesta/ssh-audit.git
cd ssh-audit
./ssh-audit.py <TARGET>
```

Kiểm tra banner và phương thức xác thực:

```bash
ssh -v <USER>@<TARGET>
```

Ưu tiên xác thực bằng mật khẩu để kiểm tra phương thức server hỗ trợ:

```bash
ssh -v <USER>@<TARGET> -o PreferredAuthentications=password
```

Banner có thể tiết lộ phiên bản OpenSSH và giúp xác định các phiên bản cần kiểm tra thêm.

## 3. Rsync

- **Port mặc định:** TCP/873.
- Công cụ đồng bộ và sao chép file giữa máy cục bộ và máy từ xa.
- Sử dụng thuật toán delta-transfer để chỉ truyền phần dữ liệu thay đổi.
- Có thể hoạt động qua SSH để tăng tính bảo mật.

### Footprinting

```bash
sudo nmap -sV -p 873 <TARGET>
```

### Liệt kê các thư mục chia sẻ

Kết nối tới dịch vụ:

```bash
nc -nv <TARGET> 873
```

Sau đó nhập:

```text
#list
```

Liệt kê nội dung một share:

```bash
rsync -av --list-only rsync://<TARGET>/<SHARE>
```

Đồng bộ file từ share được phép truy cập:

```bash
rsync -av rsync://<TARGET>/<SHARE>/
```

**Lưu ý Pentest:** Kiểm tra share có cho phép truy cập ẩn danh hay không, tìm file nhạy cảm như `secrets.yaml`, `build.sh` và thư mục `.ssh`. Không phải share nào cũng cho phép đọc file mà không cần xác thực.

## 4. R-Services

R-Services là tập hợp giao thức truy cập từ xa trên Unix, truyền dữ liệu không mã hóa và đã phần lớn được thay thế bằng SSH.

### Các cổng và lệnh quan trọng

| Lệnh | Port TCP | Chức năng |
|---|---:|---|
| `rexec` | 512 | Thực thi lệnh từ xa, sử dụng username/password |
| `rlogin` | 513 | Đăng nhập vào máy từ xa |
| `rsh` | 514 | Thực thi lệnh hoặc mở shell từ xa |
| `rcp` | 514 | Sao chép file giữa các máy |

### Footprinting

```bash
sudo nmap -sV -p 512,513,514 <TARGET>
```

### Cơ chế tin cậy nguy hiểm

Hai file cấu hình quan trọng:

- `/etc/hosts.equiv`: quy định các host được tin cậy trên toàn hệ thống.
- `~/.rhosts`: quy định host và user được tin cậy cho từng tài khoản.

Ví dụ cấu hình nguy hiểm:

```text
+ +
```

Ký tự `+` có thể đại diện cho phạm vi tin cậy rộng. Cấu hình quá rộng có thể cho phép truy cập mà không cần thông tin xác thực thông thường.

### Kiểm tra truy cập

```bash
rlogin <TARGET> -l <USER>
```

Liệt kê người dùng đang đăng nhập:

```bash
rwho
```

Lấy thông tin chi tiết hơn:

```bash
rusers -al <TARGET>
```

Các thông tin thu được có thể hỗ trợ xác định username, hostname và những máy đang có phiên đăng nhập.

## 5. Tổng kết Pentest

| Dịch vụ | Port | Nội dung cần kiểm tra |
|---|---|---|
| SSH | TCP/22 | Phiên bản, thuật toán yếu, cấu hình xác thực, quyền root, mật khẩu yếu |
| Rsync | TCP/873 | Share công khai, file nhạy cảm, quyền đọc/ghi, mật khẩu tái sử dụng |
| R-Services | TCP/512–514 | Dữ liệu không mã hóa, cấu hình `hosts.equiv` và `.rhosts`, truy cập không cần xác thực |

### Biện pháp khắc phục

- Ưu tiên SSH-2, cập nhật OpenSSH và loại bỏ thuật toán yếu.
- Sử dụng mật khẩu mạnh hoặc public key; hạn chế đăng nhập root trực tiếp.
- Giới hạn truy cập dịch vụ quản trị bằng firewall và phân đoạn mạng.
- Kiểm soát quyền truy cập Rsync, không công khai file nhạy cảm.
- Vô hiệu hóa R-Services nếu không cần thiết; thay thế bằng SSH.
- Kiểm tra và loại bỏ các quy tắc tin cậy quá rộng trong `hosts.equiv` và `.rhosts`.

**Ghi nhớ:** Trong Linux Remote Management Pentest, hãy ưu tiên tìm cấu hình sai, share có thể đọc được, thông tin xác thực bị tái sử dụng và quan hệ tin cậy cho phép truy cập trái phép.
